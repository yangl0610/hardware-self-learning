# C++ 语言

C++ 在 C 的基础上增加了类、模板与自动资源管理。嵌入式开发中通常只使用其中开销小的部分：类、模板与 RAII 思想，避开异常处理和大量动态分配。本章介绍这些内容及其工程取舍。

## 命名空间与引用

### 命名空间

命名空间用于避免命名冲突：标准库位于 `std` 命名空间，自定义代码也可以组织在自己的命名空间中。

``` cpp
namespace bsp {
    int init();
}
/* 调用：bsp::init(); */
```

使用时可以写完整的 `bsp::init()`，也可以用 `using` 声明：`using bsp::init;` 只引入需要的名字，`using namespace bsp;` 引入整个命名空间。头文件中不要用 `using namespace`——会把名字泄露给所有包含它的文件，容易冲突；只在本文件内使用的辅助符号可以放进匿名命名空间，效果相当于 C 的 `static`。

### 引用

引用是变量的别名，必须初始化，且不能改指其他变量：

``` cpp
int x = 10;
int &r = x;    /* r 是 x 的别名 */
r = 20;        /* x 变为 20 */
```

函数传参时使用常量引用 `const T&`：既不复制实参（效率高），也不允许修改（安全）。这是 C++ 函数接口的标准写法。引用与指针的差别：引用必须绑定到有效对象、不能为空、不能改指；指针可以为空、可以重新指向。因此引用参数无需空指针检查；返回大对象时用引用（或常量引用）避免复制，接口内部可能为空时应改用指针。

### 函数重载

同名函数可以有不同的参数列表，称为函数重载：编译器按实参的类型与个数在编译期选择对应版本。它让一组功能相近的操作共用同一个名字，例如多个初始化函数可以都叫 `init`。

## 类与封装

类把数据和操作数据的函数组合在一起，通过访问控制限定外部可见的部分：

``` cpp
class Led {
public:
    Led(int pin) : pin_(pin) {}
    void on();
    void off();
private:
    int pin_;
};
```

构造函数在对象创建时初始化成员，成员在初始化列表中进行初始化（而不是在函数体内赋值）是规范做法。析构函数在对象销毁时自动调用，用于释放资源。与 C 语言相比，类把"初始化"和"清理"与对象的生命周期绑定，不会遗漏。

### 封装与类外定义

封装可以实现三层效果：数据与操作绑定在一起；对外只暴露必要的接口，实现细节（`private`）可以随时更换；调用方只依赖接口，不依赖实现。类内声明的成员函数也可以在类外定义，函数名前加类名与作用域运算符：`void Led::on() { /* ... */ }`。成员函数内部访问成员时隐含一个指向当前对象的指针 `this`：`this->pin_` 与 `pin_` 等价；静态成员函数没有 `this`。

### const 成员函数

在成员函数声明末尾加 const，表示该函数不修改对象状态：

``` cpp
int value() const { return value_; }
```

类的接口应尽量把只读取数据的函数声明为 const，便于编译器检查。

!!! example "例题"

    **例 19.1**用类封装一个 GPIO 输出引脚的基本操作。

    **解**：

    ``` cpp
    class Gpio {
    public:
        Gpio(volatile uint32_t *port, int pin)
            : port_(port), pin_(pin) {}
        void set()    { *port_ |=  (1U << pin_); }
        void clear()  { *port_ &= ~(1U << pin_); }
        void toggle() { *port_ ^=  (1U << pin_); }
    private:
        volatile uint32_t *port_;
        int pin_;
    };
    ```

    接口比裸寄存器操作清晰得多，便于在多个项目中复用。

## 继承与多态

### 继承

继承表示"是一种"的关系，派生类复用基类的接口与实现：

``` cpp
class Sensor {
public:
    virtual float read() = 0;   /* 纯虚函数 */
    virtual ~Sensor() {}        /* 虚析构函数 */
};
class Thermistor : public Sensor {
public:
    float read() override;
};
```

### 多态

用基类指针调用同一接口，不同对象表现出不同行为，这就是多态。实现机制通常为虚函数表：含虚函数的类，其对象中有一个指向虚函数表的指针，调用时经表查找。代价是少量内存与一次间接跳转，资源紧张的系统需酌情使用。

两条实践规则：当会通过基类指针删除派生类对象时，基类的析构函数必须声明为 virtual；能用组合（"有一个"）表达的关系，不用继承。

另一条规则来自构造与析构的顺序：构造时基类先构造、派生类后构造，析构时派生类先析构、基类后析构——这正是通过基类指针删除对象时要求虚析构函数的原因。`override` 让编译器检查确实覆盖了基类虚函数，拼写错误会直接报错。还要注意对象切片：把派生类对象按值传给基类参数会只保留基类部分、丢失多态，这正是多态要用指针或引用传递的原因。

!!! example "例题"

    **例 19.2**用基类指针统一处理两种传感器的读数。

    **解**：

    ``` cpp
    void printAll(Sensor **s, int n)
    {
        for (int i = 0; i < n; i++) {
            printf("%.2f\n", s[i]->read());
        }
    }
    /* Thermistor th; Imu imu; */
    Sensor *list[2] = { &th, &imu };
    printAll(list, 2);
    ```

    调用方只依赖 `Sensor` 接口，新增传感器类型不需要改动打印逻辑。

## 模板

模板让代码适用于多种类型，在编译期展开，运行时没有额外开销：

``` cpp
template <typename T, int N>
class RingBuffer {
public:
    void push(T v);
    T pop();
private:
    T buf[N];
    int head = 0, tail = 0;
};
```

固定容量环形缓冲区、定点数学函数、寄存器封装，都是嵌入式模板的典型用法。模板的类型检查在编译期完成，比宏定义安全得多。函数模板同理：

`template <typename T> void swap2(T &a, T &b)`

对任意可赋值类型都成立。使用时显式实例化，如 `RingBuffer<int, 8> rb;`——模板参数必须是编译期常量，容量、引脚号等正合适。代价是每种实例都生成一份独立代码，类型组合多时体积会增大，嵌入式工程要控制实例数量。

## RAII 与自动资源管理

RAII 的含义是：在构造函数中获得资源，在析构函数中释放资源；对象离开作用域时，资源自动归还。无论函数是正常返回还是中途返回，清理都会发生。

智能指针是这一思想的直接应用：

| 智能指针   | 所有权 | 说明                                       |
|:-----------|:-------|:-------------------------------------------|
| unique_ptr | 独占   | 与裸指针相同（无额外运行时开销），优先使用 |
| shared_ptr | 共享   | 有引用计数开销，谨慎使用                   |
| weak_ptr   | 不拥有 | 配合 shared_ptr 解决循环引用               |

三种智能指针

以 `unique_ptr` 为例：`auto p = std::make_unique<Adc>(1);`——创建后在作用域结束时自动释放，不再需要手写 `delete`；所有权转移用 `std::move`，同一时刻只有一个所有者。`shared_ptr` 有引用计数开销，嵌入式环境一般避免使用。

嵌入式也可以利用 RAII 简化临界区管理：构造时保存并关闭中断、析构时恢复中断状态的守卫对象，保证中途提前返回时也能正确恢复。

``` cpp
class IrqGuard {
public:
    IrqGuard()  { primask_ = save_and_disable(); }
    ~IrqGuard() { restore(primask_); }
private:
    uint32_t primask_;
};
/* 作用域结束时自动恢复中断 */
```

## 标准库容器与嵌入式取舍

| 容器   | 结构     | 用途                  |
|:-------|:---------|:----------------------|
| array  | 定长数组 | 替代 C 数组，推荐使用 |
| vector | 动态数组 | 通用列表              |
| string | 字符串   | 文本处理              |
| map    | 查找表   | 键值查询              |

常用标准库容器

标准库容器默认使用堆内存。资源受限的单片机可以改用带静态存储的定长容器实现，或为容器指定自定义分配器。范围 for 循环可以简化容器遍历：

``` cpp
for (auto &x : arr) { x += 1; }
```

## 嵌入式 C++ 的使用建议

- 适合使用：类封装驱动、命名空间、const、模板、RAII；

- 谨慎使用：异常、运行时类型识别、输入输出流（体积大）、大量动态多态；

- 常用编译选项：关闭异常与 RTTI（`-fno-exceptions -fno-rtti`），减小代码体积；

- C 与 C++ 混编：C 语言的头文件用 `extern "C"` 包裹，避免名字改编导致的链接错误。
