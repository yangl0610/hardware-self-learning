# 汇编

汇编指令与处理器硬件一一对应。实际开发很少直接用汇编写程序，但反汇编用于定位崩溃、检查编译器输出、理解函数调用与中断过程。本章以 ARM Cortex-M 为例介绍汇编基础。

## 寄存器

| 寄存器      | 名称             | 用途                                   |
|:------------|:-----------------|:---------------------------------------|
| R0$\sim$R3  | 参数与临时寄存器 | 传递参数、存放返回值                   |
| R4$\sim$R11 | 被保存寄存器     | 被调用者修改前须保存、返回前恢复       |
| R12         | 临时寄存器       | 供链接器生成的过渡代码使用的暂存寄存器 |
| R13         | 栈指针 SP        | 指向栈顶                               |
| R14         | 链接寄存器 LR    | 保存函数返回地址                       |
| R15         | 程序计数器 PC    | 指向当前指令                           |
| xPSR        | 状态寄存器       | 标志位与中断状态                       |

Cortex-M 通用寄存器及用途

状态寄存器中的标志位是条件执行的依据：运算结果为零置 Z、为负置 N、产生进位或借位时置 C、有符号溢出置 V。`CMP` 之类的指令就是根据结果设置这些标志；后面的条件跳转（如 `BEQ`）或条件执行（`IT EQ` 后接条件指令）都是在使用刚刚设置的标志：先算、再看标志、再决定动作。

## 寻址方式

| 方式 | 写法示例 | 含义 |
|:---|:---|:---|
| 立即数 | `MOV R0, #8` | 使用常数值 |
| 寄存器间接 | `LDR R0, [R1]` | 读取 R1 所指地址的内容 |
| 带偏移 | `LDR R0, [R1, #4]` | 读取偏移 4 字节处的内容 |
| 带写回 | `LDR R0, [R1, #4]!` | 读取后自动把 R1 加 4 |
| PC 相对 | `LDR R0, [PC, #4]` | 读取 PC 附近常量池中的数据 |
| 多寄存器 | `PUSH {R4, LR}`、`POP {R4, PC}` | 一次传输多个寄存器，常用于压栈与返回 |

常用寻址方式

带偏移方式常用于访问结构体成员；带写回方式用于遍历数组。加载任意 32 位常量（如外设地址）的惯用写法是 `LDR R0, =0x40020000`：这里的 `=` 是伪指令，因为 `MOV` 只能编码有限位宽的立即数，任意 32 位常量会被汇编器放进附近的常量池（文字池），再以 PC 相对寻址加载。压栈后 SP 向低地址方向变化，这就是栈向下生长的含义。

## 常用指令

| 类别 | 指令 | 作用 |
|:---|:---|:---|
| 搬运 | MOV、LDR、STR、PUSH、POP | 数据移动与栈操作 |
| 字节/半字访问 | LDRB、STRB、LDRH、STRH | 按 8 位/16 位读写（外设寄存器常用） |
| 算术 | ADD、SUB、MUL | 加减乘 |
| 逻辑 | AND、ORR、EOR、BIC、LSL、LSR | 位运算与移位 |
| 比较 | CMP、TST | 设置标志位 |
| 跳转 | B、BL、BX | 跳转、调用、返回 |
| 特殊寄存器 | MRS、MSR、CPSID、CPSIE | 读写状态寄存器、开关中断 |

常用指令

BL 用于调用函数：它自动把下一条指令的地址存入 LR；函数返回时执行 `BX LR`。A32 指令集中的大部分指令可带条件后缀；Cortex-M 使用的 Thumb-2 指令集需要先用 `IT` 构成条件块，例如 `CMP R0, #5` 后接 `IT EQ` 与 `ADDEQ R1, #1`，表示两数相等时才执行加法，不必借助跳转。

Cortex-M 的 Thumb-2 指令集为 16 位与 32 位混合编码，常用的简单指令为 16 位，代码密度高，适合存储资源有限的应用。

## 函数调用与 ABI

### 调用约定

应用二进制接口（ABI）规定了函数之间交换信息的方式：

- 前四个参数放在 R0$\sim$R3，更多参数通过栈传递；

- 返回值放在 R0，64 位返回值占用 R0 与 R1；

- 调用者负责保存 R0$\sim$R3 与 R12（若需要）；被调用者负责保存用到的 R4$\sim$R11 与 LR。

编译器按上述规则自动生成代码。超出四个的参数由调用者提前放到栈顶，被调用者用 `[SP, #0]`、`[SP, #4]` 相对访问；帧指针（R11/FP）标记当前栈帧的基准，便于调试器回溯调用链，优化后可能不保留。

### 栈帧

函数执行时在栈上建立栈帧，一般包含：超出四个的传入参数、返回地址、被保存的寄存器、局部变量。深层调用与递归中，LR 会在每次调用时被覆盖，因此必须先把旧值压栈保存，这正是栈帧存在的重要原因。

一个函数的典型汇编框架为：

``` asm
my_add:
    PUSH {R4, LR}      /* 保存将被改动的寄存器与返回地址 */
    ADD  R0, R0, R1    /* 函数体：两数相加 */
    POP  {R4, PC}      /* 恢复寄存器并返回 */
```

!!! example "例题"

    **例 21.1**在 -O0（不优化）下，函数 `int add(int a, int b)` 编译后，两个参数在哪个寄存器中？返回值放在哪里？

    **解**：参数 $a$ 在 R0，$b$ 在 R1；加法结果写回 R0 后返回。

## 中断与异常

中断发生时，硬件自动完成以下工作：

1.  把 R0$\sim$R3、R12、LR、PC、xPSR 共八个寄存器压入栈，保存现场；

2.  从向量表中取出中断服务函数的地址并跳转；

3.  中断处理完毕，执行返回指令，硬件自动恢复现场。

由于现场由硬件保存，中断服务函数可以直接用 C 语言编写，编译器会按 ABI 生成正确代码。硬件压入的八个寄存器共占 32 字节栈空间（$8\times4$），都属于调用者保存类别；其余寄存器若在中断服务函数中使用，由编译器按 ABI 自动保存与恢复。返回机制：压栈时硬件存入一个特殊的返回码，返回指令据此恢复到中断前的状态，因此中断服务函数按常规方式返回即可。多个中断同时到来时按 NVIC 优先级仲裁，高优先级可以打断低优先级（嵌套）。

调试死机（如 HardFault）的定位方法：先查看故障状态寄存器判断异常类型，再从异常栈帧里取出 PC 值（出错处地址），在反汇编中找到对应指令——多数情况是访问了非法指针或数组越界。

## C 与汇编混合编程

- C 调用汇编函数：按 ABI 约定传参，函数结尾用 `BX LR` 返回；

- 汇编调用 C 函数：用 `BL` 跳转，调用前保存需要保留的寄存器；

- C 中嵌入汇编：使用 `__asm volatile` 语句，volatile 防止被优化删除；

- 启动文件是系统上电后执行的第一段代码，用汇编编写：建立栈、初始化 `.data` 段并清零 `.bss` 段、跳转到 `main`。

按 ABI 写一个最小的汇编函数，并在 C 中声明调用：

``` asm
/* 汇编侧：参数在 R0/R1，结果写回 R0 */
asm_add:
    ADD R0, R0, R1
    BX  LR
```

`int asm_add(int a, int b);` 声明后即可像普通函数一样调用。在 C 中访问特殊寄存器则用内联汇编：

``` asm
static inline uint32_t get_primask(void)
{
    uint32_t v;
    __asm volatile ("MRS %0, PRIMASK" : "=r"(v));
    return v;
}
```

## 反汇编判读与优化

### 优化等级

| 等级 | 目标               | 适用场合         |
|:-----|:-------------------|:-----------------|
| -O0  | 不做优化，便于调试 | 开发阶段         |
| -O2  | 平衡速度与体积     | 发布版本常用     |
| -Os  | 优先减小体积       | Flash 紧张的场合 |

常用编译优化等级

### 优化后的代码特征

- 小函数被内联，调用处看不到 BL 指令；

- 循环被展开，指令数量变化明显；

- 变量被保存在寄存器中，看不到对应的内存访问；

- 带 volatile 的变量每次仍会从内存读取，在反汇编中可以明显看出。

判读反汇编的方法：先找到函数入口，确认各参数所在的寄存器，沿 B、BL 等跳转指令跟踪流程，观察 SP 的变化判断栈开销。常见 C 结构到汇编的对应模式：if 与循环是“比较 + 条件跳转 + 回跳”；函数调用是“PUSH 保存 + BL + POP 恢复”；指针访问先取地址再用 `[Rn]` 访问；局部变量很小时只存在于寄存器中，栈上找不到。按模式对照，比逐条指令猜测快得多。

!!! example "例题"

    **例 21.2**在 -O2 优化下，为什么断点有时无法停在某个变量上？

    **解**：变量可能已被保存在寄存器中，甚至被完全消除（其值可由其他表达式直接算出），不存在可设置断点的内存地址。这是调试版本使用 -O0 的原因。

!!! example "例题"

    **例 21.3**阅读以下反汇编片段，判断函数接收几个参数、返回值来自哪个寄存器。

    ``` asm
    func:
        PUSH {R4, LR}
        CMP  R0, #0
        IT   EQ
        MOVEQ R0, #1
        ADD  R0, R0, R1
        POP  {R4, PC}
    ```

    **解**：使用了 R0 与 R1，说明接收两个参数；结果累加到 R0，返回值来自 R0（符合 ABI）；PUSH 与 POP 成对出现，栈开销为两个寄存器。
