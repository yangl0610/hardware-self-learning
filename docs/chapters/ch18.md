# C 语言

C 语言是嵌入式开发的主要语言。它能够直接操作内存：数组名在表达式中等价于指向首元素的指针，函数参数按值传递，外设寄存器可以看作固定地址上的变量。本章介绍 C 语言的基础知识，以及嵌入式开发中的常用写法。

## 程序结构与编译过程

一个 C 程序由若干源文件组成，每个源文件（`.c`）通常配一个头文件（`.h`）。头文件放声明，源文件放实现。

从源码到可执行程序经过四步：

预处理（处理 `#include` 与 `#define`）$\to$ 编译（生成汇编）$\to$ 汇编（生成目标文件）$\to$ 链接（合并为可执行文件）

其中链接阶段解决函数之间的相互引用，并把启动代码与库拼接进来；可执行文件从 `main` 函数开始执行。

## 数据类型与变量

### 基本类型

| 类型 | 典型长度 | 典型范围 | 说明 |
|:---|:---|:---|:---|
| char / uint8_t | 1 字节 | $0\sim255$（有符号 $-128\sim127$） | 字符、字节数据 |
| short / uint16_t | 2 字节 | $0\sim65535$ | 中等范围整数 |
| int / uint32_t | 4 字节 | $0\sim$ 约 $4.3\times10^{9}$ | 嵌入式建议用明确宽度的标准类型 |
| float | 4 字节 | 约 7 位有效数字 | 通用浮点运算 |
| double | 8 字节 | 约 15 位有效数字 | 部分单片机以软件模拟实现，速度慢 |

基本数据类型

表中每行同时给出传统类型与 `<stdint.h>` 的定宽类型，长度为 32 位平台的典型值；`int` 的长度随平台变化，跨平台或与硬件交互时应使用定宽类型。

有符号与无符号混合运算容易出错：有符号与无符号运算时，有符号数会先转换为无符号数；两个无符号数相减，若结果为负会回绕成一个很大的正数，与直觉相反。嵌入式代码中尽量统一使用无符号类型表示长度、计数等非负量；另一个典型陷阱是整数回绕——uint8 型的 255 加 1 变为 0、0 减 1 变为 255，选类型时按实际量程留足余量。

### 运算符与表达式

算术运算符 `+ - * / %` 中，两个整数相除会舍去小数部分，取余用 `%`。关系运算符 `== != > < >= <=` 的结果为真（1）或假（0）；逻辑运算符 `&&`、`||`、`!` 用于组合条件。注意 `=` 是赋值，`==` 才是判断相等。运算符有优先级，不确定时加括号。

### 作用域与生命周期

局部变量存放在栈上，函数返回即失效；全局变量和静态变量在整个程序运行期间存在。

关键字 static 有三种用法：修饰函数，使其只在本文件内可见；修饰全局变量，使其只在本文件内可见；修饰局部变量，使其在两次函数调用之间保持数值。

关键字 const 表示只读：修饰变量表示该值不应被修改；修饰指针参数表示函数不会改动传入的数据。合理使用 const 能让编译器帮助发现错误。

## 函数与控制流

函数由返回类型、函数名、参数表和函数体组成，用 `return` 返回结果。控制流包括 if、for、while、switch 等语句：`for(初始化; 条件; 更新)` 的执行顺序固定，适合按下标遍历；`while` 先判断后执行；`do-while` 至少执行一次。`break` 提前退出循环或 switch 分支，`continue` 跳过本次循环的剩余部分。使用 switch 时每个分支末尾要加 break，否则会继续执行下一个分支。

``` c
uint32_t sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];        /* 累加数组元素 */
}
```

函数参数按值传递：函数内部得到的是实参的副本，修改副本不影响外部变量；要修改外部数据，必须传递指针。这一规则是理解后续指针用法的基础。

函数指针保存函数的入口地址，用于回调、状态机表等场合：

``` c
typedef void (*handler_t)(void);
handler_t table[4] = {func0, func1, func2, func3};
```

## 指针与数组

### 指针基础

指针存放变量的地址：

``` c
int x = 10;
int *p = &x;    /* p 指向 x */
*p = 20;        /* 通过指针写入 */
```

基本关系：

- 数组名相当于指向首元素的指针，$a[i]$ 等价于 $*(a+i)$；

- 指针加 1 移动一个元素的距离，步长由所指类型决定；

- 向函数传递数组，实际传递的是首地址，因此函数内可以修改数组内容；

- 字符串是以 `'\0'` 结尾的字符数组。

数组用于存放同类型的多个元素：`int a[5] = {1, 2, 3, 4, 5};`，下标从 0 开始；对数组名使用 `sizeof` 得到整个数组的字节数，而对指针使用 `sizeof` 只得到指针本身的大小——这一点很容易混淆。

例如 `char buf[16] = "abc";` 中，数组占用 16 个字节，字符串 `"abc"` 连同结尾符 `'\0'` 占用其中 4 个字节。常用操作（来自 `<string.h>`）：`strlen` 求长度（不计结尾符）、`strcpy` 复制、`strcmp` 比较（相等返回 0）。使用 `strcpy` 前必须确认目标缓冲区足够大，否则会越界写入。

``` c
char name[16] = "UART";
if (strcmp(name, "UART") == 0) {
    /* 两者相等 */
}
```

!!! example "例题"

    **例 18.1**编写交换两个整数的函数。

    **解**：按值传递无法修改实参，必须传入指针：

    ``` c
    void swap(int *a, int *b)
    {
        int t = *a;
        *a = *b;
        *b = t;
    }
    /* 调用：swap(&x, &y); */
    ```

### const 指针与空指针

在 `const int *p` 中，指针指向的内容不可改；在 `int * const p` 中，指针自身的指向不可改。函数接口中常用前者保护输入数据。

指针在使用前必须指向有效内存。未初始化或指向无效位置的指针称为野指针，指向已释放内存的指针称为悬空指针；解引用都会导致程序崩溃，这类问题往往难以定位，因此指针参数在函数入口处应做空指针检查。

## 内存模型

### 五个区域

| 区域   | 存放内容               | 特点                     |
|:-------|:-----------------------|:-------------------------|
| 栈     | 局部变量、函数调用信息 | 自动分配释放，快，容量小 |
| 堆     | 动态申请的内存         | 手动管理，易产生碎片     |
| 静态区 | 全局变量、静态变量     | 全程存在                 |
| 常量区 | 字符串字面量、常量     | 只读                     |
| 代码区 | 程序指令               | 只读                     |

程序内存的五个区域

嵌入式程序以栈和静态区为主，堆使用较少：动态分配存在碎片化与失败不可预测的问题，不适合长期稳定运行的实时系统。

### 对齐与 sizeof

结构体成员按对齐要求存放，编译器可能在成员之间填充空字节，因此结构体的大小可能大于各成员大小之和。运算符 sizeof 的结果在编译阶段确定。

掌握这两个概念可以解释很多实际问题：协议帧的解析要对齐、外设数据缓冲区的大小要按实际布局计算。

## 结构体、联合体与位域

### 结构体

结构体把多个相关变量组合成一个整体，适合描述寄存器组、传感器数据和协议帧。通过指针访问成员时使用箭头运算符：

``` c
typedef struct {
    uint32_t CR;
    uint32_t SR;
    uint32_t DR;
} UartRegs;
```

### 联合体

联合体让多个成员共用同一块内存，同一段数据可以按不同方式解释，常用于把 32 位数据拆成字节，或进行协议字段的多种解读。

### 位域与寄存器映射

位域可以为寄存器中的每个位起名字（其内存布局由编译器实现决定，不同平台可能不同）：

``` c
typedef struct {
    uint32_t EN    : 1;
    uint32_t MODE  : 2;
    uint32_t RSVD  : 5;
} CtrlReg;
```

嵌入式 C 中最基本的写法是把外设寄存器定义成结构体指针，通过箭头运算符访问成员：

``` c
#define GPIOA ((GPIO_TypeDef *)0x40020000UL)
GPIOA->ODR |= (1U << 5);   /* 把 PA5 置 1 */
```

## 位操作

| 目的     | 运算         | 写法                               |
|:---------|:-------------|:-----------------------------------|
| 置 1     | 或           | `reg |= (1U << n)`                 |
| 清 0     | 与取反       | `reg &= ~(1U << n)`                |
| 翻转     | 异或         | `reg ^= (1U << n)`                 |
| 读取某位 | 右移后与 1   | `(reg >> n) & 1U`                  |
| 修改多位 | 先清零再赋值 | `reg = (reg & ~mask) | (val << n)` |

常用位操作

常量后加 U 表示无符号数：例如 `1U << 31` 不会触发有符号溢出。

!!! example "例题"

    **例 18.2**把变量 `flags` 的第 3 位清零，同时把第 0 位置 1。

    **解**：

    ``` c
    flags &= ~(1U << 3);
    flags |=  (1U << 0);
    ```

## 模块化

工程代码按层次组织：驱动层直接操作寄存器，中间层实现协议与算法，应用层实现业务逻辑。

头文件用条件编译防止重复包含：

``` c
#ifndef LED_H
#define LED_H
/* 声明 */
#endif
```

`extern` 用于声明在别的文件中定义的变量；`static` 函数与 `static` 全局变量只在本文件内可见，用于隐藏实现细节。

## 嵌入式 C 的常用要点

- volatile：告诉编译器该变量可能被程序之外的因素改写（中断、硬件），每次使用都必须从内存重新读取。硬件寄存器、中断与主程序共享的变量、DMA 缓冲区必须加此修饰符。

- 临界区：中断与主程序共享多字节变量时，"读—改—写"过程可能被打断，需要用关中断或原子操作保护。

- 库的选择：HAL 库跨芯片、便于移植但代码较大；LL 库接近寄存器、效率高；直接操作寄存器效率最高，需要对照手册。一般先用 HAL 跑通功能，再对关键部分用 LL 或寄存器优化。

- 浮点打印：部分平台默认不支持 printf 输出浮点数，需要开启相应选项或改用整数方式打印。

!!! example "例题"

    **例 18.3**声明一个由中断修改、主程序读取的标志变量。

    **解**：

    ``` c
    volatile uint8_t g_flag;
    ```

    不加 volatile 时，主循环中的 `while(!g_flag)` 可能被编译器优化成只读一次内存，导致死循环。
